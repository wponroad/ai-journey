## 二、三个问题

### ① 哪个认知被推翻了？

**六个，全是"以为懂了"。**

| 我以为 | 实际 |
|---|---|
| 抖动 = 指数退避 + 一点随机 | **`UseJitter` 会取代指数退避**，实测 `1.4s → 0.8s`，是递减的 |
| 重试 3 次 + 单次 12s + 总 30s 能共存 | `12×3 + 退避 = 39 > 30`，第 3 次重试**根本跑不到** |
| 熔断参数按调用次数配就行 | 采样窗口 30s **小于一次请求的 34s**，样本被滑出，熔断**永远不打开** |
| 失败了至少知道花了多少钱 | **超时的请求没有 response，就没有 usage**，钱可能花了但完全不可见 |
| 语义缓存只对"意思相近"生效 | `…109` vs `…110` 相似度 **0.9892**，比同义改写的 0.9543 还高 |
| 一次对话慢，肯定是模型慢 | **缓存查询 5.75 秒**，模型只占一半 |

**共同点：全都是"配置看起来合理、代码没有报错、但功能不工作"。**

这一类问题的可怕之处在于——**你不会去查它**。因为没报错，你会以为它在工作。

### ② 哪个结论只能实测得到？

三条，靠推理和文档都得不到：

**1. 抖动的真实行为**

文档只说"加随机"。实测才看到 `1.4s → 0.8s`，才知道 Polly 用的是 decorrelated jitter（`random(base, prev×3)`），才知道"单次可减、长期递增"。

**2. 相似度阈值切不开**

我以为"阈值 0.95 就能拦住不同订单"。量完才知道：**该拦的 0.9892，想命中的 0.9543 —— 顺序是反的。**

任何单一阈值都做不到"命中改写、排除实体替换"。这不是调参问题，是**这两类在向量空间里不可分**。

**3. 冷启动的代价**

"第一次调用会慢一点"——慢多少？**5.75 秒，比模型本身还慢。**

而且这个数字只有在 OTel 拆开之后才看得见。之前只知道总耗时 21 秒，会一直以为是模型慢。

> **这三条的共同点：涉及的数值没法靠直觉估。**
> 我事先估的三个相似度全错，而且方向一致（低估基线、高估区分度）。

### ③ 哪些能直接搬进项目①？

项目①的范围已经定死：**多 provider 路由 + 流式 + 重试 + 计费 + 日志**。

| W3 做的 | 带不带走 | 说明 |
|---|---|---|
| 重试（指数退避 + 抖动） | ✅ **带走** | 直接复用，参数按 provider 可配 |
| 超时（单次 + 总时长） | ✅ **带走** | 注意预算关系 |
| 熔断 | ✅ **带走** | 采样窗口要盖住一次请求的最坏耗时 |
| 降级（规则兜底） | ✅ **带走** | 这是「网关不能把错误直接抛给业务」的核心 |
| 计费（SQLite） | ✅ **带走，换存储** | 表结构直接搬，SQLite → MySQL/PG |
| 日志 / OTel | ✅ **带走** | 网关没有可观测性等于没有 |
| 单元测试 + FakeChatClient | ✅ **带走** | 换个 provider 就能复用 |
| **缓存（精确 + 语义）** | ❌ **不带** | **不在项目①范围里** |

**最后一行是这次复盘最重要的判断。**

语义缓存很酷，实体守卫也想清楚了，但**任务卡明确写了网关只做那五件事**。加缓存 = 多一周 = 少一周 RAG。

> 范围一旦定死就不要再加功能。**做减法比做加法难，但这一步决定了项目能不能按时开出来。**

## 三、W3 门槛自查

门槛原文：**「制造 429 时系统自动退避且不崩；能当场报出某次对话花了多少钱、慢在哪一步」**

| 要求 | 证据 | 状态 |
|---|---|---|
| 429 自动退避 | D1 实测 `[retry 1] 等 1.4s → [retry 2] 等 0.8s → 放行` | ✅ |
| 不崩 | D2 熔断打开 → 降级返回规则答案，用户看不到报错 | ✅ |
| 不雪崩 | D6 并发 20 个 429，真实调用 **4 次**（无熔断是 100 次） | ✅ |
| 花了多少钱 | D3 SQLite 账本，按用户/部门汇总 | ✅ |
| 慢在哪一步 | D5 span 树：`chat.request → cache.lookup / llm.call / tool.xxx` | ✅ |

**两条都过了，而且都有可复现的证据，不是"我觉得"。**

## 四、下周（W4）要盯的三件事

W4 是项目①开源，门槛 A 是「**陌生人 10 分钟内按 README 跑起来**」。

**① 范围守死**

只做五件事：多 provider 路由、流式、重试、计费、日志。

**任何"顺手加一下"的念头，都要先问：这是不是又开了一周的口子？**

**② README 是产品，不是文档**

门槛 A 的判据是"陌生人 10 分钟跑起来"，所以 README 的第一屏必须能回答：
- 这是什么、解决什么问题（一句话）
- 三条命令怎么跑起来
- 跑起来之后看到什么算成功

**你现在写 README 时的每一个"这里读者可能会卡"，都是门槛 A 的扣分项。**

**③ 自己先当那个陌生人**

最容易被忽略的一步：**换台干净机器（或者删掉所有本地配置）跑一遍**。

你会发现：
- 某个环境变量没写进 sample 配置
- 某个路径是绝对路径
- 某个依赖没写进 README

**这些在你自己的机器上永远不会暴露。**
