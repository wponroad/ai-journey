# W01 · Day 2　抽象与封装：IChatClient → ILLMService

> 日期：2026-11-03（周二）　项目：`projects/HelloLlm`　目标：把模型调用收进自己的 `ILLMService`  
> 一句话结论：**让业务层不认识模型 SDK，让实现层不认识具体厂商。**

## 一、`IChatClient` 到底定义了什么

查官方 API 页得到的完整定义（不是回忆）：

```csharp
public interface IChatClient : IDisposable
{
    Task<ChatResponse> GetResponseAsync(
        IEnumerable<ChatMessage> messages,
        ChatOptions? options = null,
        CancellationToken cancellationToken = default);

    IAsyncEnumerable<ChatResponseUpdate> GetStreamingResponseAsync(
        IEnumerable<ChatMessage> messages,
        ChatOptions? options = null,
        CancellationToken cancellationToken = default);

    object? GetService(Type serviceType, object? serviceKey = null);
}
```

**四个成员，其中 `Dispose()` 来自 `IDisposable`。**

### 一个容易被忽略的事实

`chat.GetResponseAsync("你好")` 这个「直接传字符串」的重载，**不在接口上**。

它是 `ChatClientExtensions` 里的扩展方法，内部做的事就是：

```
string → new ChatMessage(ChatRole.User, text) → 调接口上那个收消息列表的方法
```

所以这个抽象被故意做得最小：**核心只认消息列表**，便利性靠扩展方法补。和 `IEnumerable<T>` 配一堆 LINQ 扩展是同一套设计。

**直接推论**：接口收的是列表，列表多长由调用方决定，服务端不记 —— 这就是「LLM 的 HTTP 接口无状态」在代码里的样子。

## 二、`GetService` 是干什么的（我一开始想错了）

我原来的理解：*多个客户端注入以后，靠它切换不同模型。* **错的。**

切换用哪个实现，是 DI 容器的事，和接口方法无关。`GetService` 是**挖取底层对象的逃生舱口**——抽象只覆盖各家共有的能力，厂商特有的东西靠它往下捞。

三个真实用途：

| 用途         | 例子                                                           |
| ---------- | ------------------------------------------------------------ |
| 取元数据       | `GetService<ChatClientMetadata>()` 拿到 provider 名、模型 id，用来打日志 |
| 取底层 SDK 对象 | `GetService<OpenAIClient>()` 访问抽象没暴露的厂商特性                    |
| 装饰器链       | 写中间件（日志/重试/计费）时，沿链找内层 client                                 |

一句话：**逃生舱口，不是路由开关。**

## 三、`IDisposable`

|       | GC                | `Dispose()`                   |
| ----- | ----------------- | ----------------------------- |
| 管什么   | 托管内存（`new` 出来的对象） | 非托管资源：socket、文件句柄、数据库连接       |
| 什么时候  | 不确定，由 GC 决定       | 确定，由 `using` 或容器决定            |
| 不管会怎样 | 内存涨               | **socket 耗尽**（连接堆在 TIME_WAIT） |

`IChatClient` 要 `IDisposable`，是因为它内部持有 HttpClient 和连接池。**不 Dispose 的后果是连接泄漏，类似于数据库连接。**

而且：**Dispose 不会自动发生。** 只有两种情况会被调用——`using` / `await using`，或者交给 DI 容器在作用域结束时（Transient/Scoped 会，Singleton 要等容器销毁）释放。

## 四、ILLMService 创建的意义

ILLMService创建的意义：这层服务不用管IChatClient到底是什么大模型，只是用大模型，构建对话，获取返回值，并把自己想要的数据进行加工，例如：可以在这个地方后期写日志等

这一层将来要承载日志、成本、流式，所以它抽取出来是很有必要的。
