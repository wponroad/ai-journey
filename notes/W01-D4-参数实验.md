# W01 · Day 4　参数实验：temperature / top_p / max_tokens

> 日期：2026-11-05（周四）　模型：qwen3:8b（本地 Ollama）/ deepseek-flash（云端）  
> 目的：三个采样参数到底改变什么，以及它们在抽象层里能不能真的送到模型。

---

## 一、实验设计

三组，**一次只动一个变量**，其余固定：

| 组 | 变量                            | 固定                | 次数    |
| - | ----------------------------- | ----------------- | ----- |
| A | Temperature 0 / 0.7 / 1 / 1.5 | 同一 prompt         | 各 1 次 |
| B | TopP 0.01 / 0.1 / 0.5 / 1.0   | Temperature = 0.7 | 各 5 次 |
| C | MaxTokens 20 / 100 / 500      | 其余默认              | 各 1 次 |

统一 prompt：`/no_think 用一句话介绍你自己。`  
**关思考是必须的**，否则 `max_tokens` 会被思考过程吃掉，正文一个字都出不来。

参数怎么进的代码：`LlmSettings`（自己的三个可空字段）→ `LlmService` 里翻译成 `ChatOptions`。  
**`ChatOptions` 没有出现在 `ILLMService` 上**，抽象层没破。

---

## 二、A 组：Temperature

模型 qwen3:8b，各跑 1 次。

| Temperature | 输出 token | 说了什么                                         |
| ----------- | -------- | -------------------------------------------- |
| 0           | 30       | 我是一个本地部署的AI模型，能够帮助你完成文本生成、问答、编程辅助…           |
| 0.7         | 56       | 我是一个本地部署的AI模型，能够在您的设备上高效运行，提供快速、安全的交互体验…     |
| 1           | 33       | 我是一个本地运行的AI模型，可以高效地帮助你完成…                    |
| **1.5**     | **55**   | **我是通义千问，是通义实验室自主研发的超大规模语言模型，部署在阿里云的云端服务器上** |

### 结论

**温度低 → 确定性强、可复现；温度高 → 多样化，但准确性开始崩。**

三次低温（0 / 0.7 / 1）都在说“我是本地模型”，事实正确。  
**1.5 那次说了假话** —— 它跑在这张 RTX 2060 上，却说自己部署在阿里云。

这不是巧合，是机制决定的：温度越高，概率分布被压得越平，低概率 token 也有机会被选中。  
训练语料里“通义千问 / 阿里云”这类自我介绍的概率远高于“本地部署”，**高温让它从当前上下文滑回了训练数据的高频模板。**

> **温度这个参数在生产上的真实含义：不是“让回答更有创意”，是“用准确性换多样性”。**  
> 做客服、合同审核、数据抽取这类场景，温度必须压到 0 附近。

## 三、B 组：TopP

模型 qwen3:8b，**每组跑 5 次**。

| TopP     | 5 次结果                                                       |
| -------- | ----------------------------------------------------------- |
| **0.01** | 5 次几乎完全一致：30 token，同一句话“我是一个本地部署的AI模型…”                     |
| **1.0**  | 4 次与 0.01 一致，**1 次不同**：55 token，“我是通义千问，一个由通义实验室开发的大型语言模型…” |

### top_p 的机制

**它不是“取前百分之几的答案个数”，而是“按概率从高到低累加，累计到 p 就停”。**

假设下一个 token 的分布是：

| 候选              | 概率   | 累计   |
| --------------- | ---- | ---- |
| “我是一个本地部署的AI模型” | 0.85 | 0.85 |
| “我是通义千问”        | 0.05 | 0.90 |
| 其他表达            | 0.10 | 1.00 |

- `top_p = 0.01`：累计到 0.01 就停 → **只剩第一个候选**，所以 5 次全一样
- `top_p = 1.0`：全部保留 → 那 5% 的“通义千问”**有机会被抽中**

**5 次里中 1 次 = 20%**，和“低概率路径约占 15%”的估计完全吻合。**数据是自洽的。**

### 第一次实验为什么无效

第一次每组只跑了 1 次，两组碰巧都走了主干道，看起来“毫无区别”。  
**单次采样只能证明“这次一样”，不能证明“永远一样”。**

要证伪一个概率差异，必须多次采样 —— 这就是压测为什么要跑几千次而不是一次。

### 为什么大部分时候还是一样

因为这个 prompt **答案太收敛**。问“介绍你自己”，模型几乎必然走“我是一个…”这条主干道。  
只有开放式任务（写诗、起名、头脑风暴）才会让 top_p 的差异明显放大。

**参数的效果取决于任务形态，不是固定值。**

## 四、C 组：MaxTokens —— 今天最大的发现

### 本地 qwen3:8b

| MaxTokens | 实际输出 token | 是否截断   |
| --------- | ---------- | ------ |
| **20**    | **31**     | 否，句子完整 |
| 100       | 32         | 否      |
| 500       | 53         | 否      |

设了 20，输出了 31。如果生效，句子应该在“我是一个本地运行的AI模型，能够帮助”这种地方硬断。**它没有。**

### 云端 deepseek-flash

prompt 换成三连问（`/no_think 先用一句话介绍你自己，你是本地模型还是云端模型？再做一个简要的说明你能帮助我做什么事情。`），输入 56 token。

| MaxTokens | 实际输出 token | 是否截断 |
| --------- | ---------- | ---- |
| **20**    | **217**    | 否    |
| **100**   | **180**    | 否    |
| **500**   | **329**    | 否    |

**设 20 输出 217，超了十倍多。** 三个值全部失效。

顺带一个观察：同一个 prompt 三次输出 217 / 180 / 329 token，**最长比最短多 82%**。  
又一次印证“同样的输入，输出不固定”——这次连长度都不定。

### 根因：字段名对不上

用 curl 直接打 Ollama 的 `/v1/chat/completions`，只换字段名：

| 发送的字段                        | `finish_reason` | 实际输出                   |
| ---------------------------- | --------------- | ---------------------- |
| `"max_tokens": 5`            | **`length`**    | **5 token**（内容只有“看起来”） |
| `"max_completion_tokens": 5` | **`stop`**      | **141 token**          |

**Ollama 只认 `max_tokens`，完全不认识 `max_completion_tokens`。**

而 MEAI 发给底层的正是后者。完整链条：

```
代码  ChatOptions.MaxOutputTokens = 20
  ↓  MEAI 翻译
HTTP  max_completion_tokens: 20
  ↓  Ollama 不认识这个字段
输出 31 token，finish_reason = stop（正常结束，没被截断）
```

**代码一行都没错，是中间那层按新规范发，下游还停在旧规范。**

为什么改名：OpenAI 在 2024 年底把 `max_tokens` 改成了 `max_completion_tokens`，  
因为推理模型的“思考 token”也要算进上限，原来的语义不够用了。  
MEAI 跟的是新规范，而大部分兼容层实现的是旧规范。

### DeepSeek 同样失效，根因已由官方文档确认

deepseek-flash 上现象一致：设 `max_tokens = 20`，输出 217 token，全部未截断。

查了 DeepSeek 官方接口文档（`/chat/completions` 的参数表），结论清楚：

- 参数表里**只有 `max_tokens`**，取值范围 1 ~ 384K，未设置时非思考模式默认 8K、思考模式默认 64K
- **`max_completion_tokens` 根本不在参数列表里** —— 传了会被静默忽略，与实测现象完全吻合

所以和 Ollama 是同一个根因：**MEAI 发新字段名，provider 只认旧字段名。**

### DeepSeek 官方的参数支持矩阵（文档明写）

这次查文档还翻出两条更狠的，都是**文档原文**，不是推测：

| 参数                                       | deepseek-flash 的实际行为                              |
| ---------------------------------------- | ------------------------------------------------- |
| `temperature`                            | **思考模式下不生效**                                      |
| `top_p`                                  | 非思考模式下**恒为 1.0，传入的值会被忽略**；思考模式下低于 0.95 的按 0.95 处理 |
| `max_tokens`                             | 支持，1 ~ 384K                                       |
| `frequency_penalty` / `presence_penalty` | **已废弃**，传入不产生任何效果                                 |

文档还写明：**不建议同时修改 temperature 和 top_p** —— 和第五节的结论一致。

### 顺带一个坑：`/no_think` 对 DeepSeek 无效

DeepSeek 关思考的正规参数是：

```json
"thinking": { "type": "disabled" }
```

或者：

```json
"reasoning_effort": "none"
```

**`/no_think` 是 Qwen3 的指令**，DeepSeek 不认识，只会被当成普通文本收进 prompt。

所以那天在 DeepSeek 上跑的三组 `max_tokens` 测试，**实际是在思考模式下跑的**（文档说省略 `thinking` 时默认开启思考）。  
这一点当时没意识到 —— 关思考的手段本身就不可移植。

### 判断参数是否生效，看 `finish_reason`

| `finish_reason` | 含义                    |
| --------------- | --------------------- |
| `stop`          | 模型自己说完了               |
| `length`        | **被 max_tokens 强制截断** |

设了 `max_tokens` 却拿到 `stop`，就是没生效。**服务端返回的信号比“输出看着像不像”可靠。**

## 五、两个参数的机制差异

|      | `temperature`                  | `top_p`         |
| ---- | ------------------------------ | --------------- |
| 动什么  | **缩放整个概率分布**                   | **截断候选集**       |
| 后果   | 每个 token 的选择都受影响，长度、措辞全变       | 只有“能不能选到冷门词”变了  |
| 本次实证 | A 组四次输出 30 / 56 / 33 / 55，全不一样 | B 组五次中四次一样，一次不同 |

**两者都是“降低确定性”的旋钮，机制不同，通常只调一个。**  
同时调会互相干扰，出了问题分不清是谁的锅。

## 六、幻觉有“引力中心”

两处不同参数触发了同一个幻觉，连句式都接近：

| 触发条件              | 输出                                         |
| ----------------- | ------------------------------------------ |
| Temperature = 1.5 | 我是通义千问，是通义实验室自主研发的超大规模语言模型，部署在阿里云的云端服务器上   |
| TopP = 1.0（第 5 次） | 我是通义千问，一个由通义实验室开发的大型语言模型，我可以在本地运行，也可以在云端部署 |

**幻觉不是随机的。** 模型一旦偏离当前上下文，就会滑向训练数据里最熟悉、最高频的模板。

对工程的直接含义：

- 模型出错时不会随机胡说，**它会用最熟悉的话把错误说得最像真的**
- 所以“加系统提示词明确它是谁”是有效的 —— 你在把引力中心往正确方向挪
- 这也解释了为什么评测集必须包含“事实核查”类题目，光看语言流畅度发现不了

## 七、结论

1. **Temperature 是准确性换多样性**，1.5 就开始编事实，生产场景压到 0 附近
2. **TopP 是候选集截断**，效果取决于任务形态 —— 收敛型问答看不出差异，开放式任务才明显
3. **概率现象必须多次采样**，单次对比得不出任何结论
4. **`MaxOutputTokens` 在 Ollama 和 deepseek-flash 上都静默失效**，根因是 MEAI 发新字段名、  
   兼容层只认旧字段名。**这是抽象层的系统性缺陷，不是某一家的问题**
5. **判断参数是否生效看 `finish_reason`**，不看输出像不像

第 4 条是今天最值钱的：**同一份代码，换个 provider 参数就可能失效，而且不报错。**  
这正是项目①那个网关要解决的问题 —— 网关不只是转发请求，它得做**参数适配**和**能力探测**。
